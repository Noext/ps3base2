## The four modes, corrected

```
default   : abort at 107.2 s, identical DMA error
SHADOW=1  : abort at  82.4 s, identical DMA error, 0 shadow divergences
NO_AOT=1  : NO abort in a 110 s run (exit 124, window closed normally, 3121 flips)
NO_AOT=1 on a LONGER run: abort at 102.6 s with the SAME DMA GET unmapped ea 0x0 pc 0x06428
```

So: SHADOW changes nothing (the interpreter agrees with the compiler), and NO_AOT only
DELAYS it. The defect is not in the AOT compiler and not in channel semantics. It is a
SPU DMA GET to guest address 0x00000000, size 0x80, from SPU PC 0x06428 with lsa 0x1a100,
reported as 'unmapped'. Either the guest really asks for address 0 (a structure never
filled, so its DMA-list pointer is null), or our SPU MMU says 0 is unmapped when the
console would serve it.
